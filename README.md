# バーコード識別アプリ

カメラで読み取ったバーコードが**どの規格のシンボルなのか**、**チェックデジットを持つのか**、
**各桁が何を意味するのか**を表示する Web アプリです。

解析はすべてブラウザ内で完結し、読み取ったデータは外部へ送信されません。

客先のバーコードを読み取り、**こちらの読取機をどう設定すればよいか** を出すための道具です。
形式の特定とチェックデジットの有無を調べ、機器に設定する項目の形で表示します。

PWA として作ってあります。スマートフォンのホーム画面に追加すると、
全画面のアプリとして起動し、電波がなくても動きます。

## スマートフォンで使う

1. 公開した URL をスマートフォンのブラウザで開く
2. iPhone は共有メニューから「ホーム画面に追加」、Android は「アプリをインストール」を選ぶ
3. ホーム画面のアイコンから起動する

初回に全ファイルが端末へ保存されるため、2回目以降は圏外や機内モードでも起動します。

iPhone では必ずホーム画面に追加してください。Safari で開いたままにしていると、
7日間使わなかった時点で保存データが消される仕組みがあります。
ホーム画面に追加したものはこの対象から外れます。

## 手元で動かす

カメラ API はセキュアコンテキストでのみ動作するため、`file://` で開かず HTTP サーバー経由で表示します。

```bash
python -m http.server 8765
```

ブラウザで <http://localhost:8765> を開き、「スキャン開始」を押してカメラを許可してください。

同じ LAN の PC でサーバーを立てても、スマートフォンからは使えません。
`http://<PCのIP>:8765` はセキュアコンテキストにならず、カメラもオフライン保存も動かないためです。
スマートフォンで使うには、下記の手順で HTTPS 上に公開してください。

## GitHub Pages へ公開する

このアプリはブラウザ内で完結するため、静的ファイルを置くだけで動きます。

```bash
git init
git add -A
git commit -m "バーコード識別アプリ"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

GitHub のリポジトリ画面で Settings を開き、Pages の項目で Source を
`Deploy from a branch`、ブランチを `main`、フォルダを `/ (root)` に設定します。
数分で `https://<ユーザー名>.github.io/<リポジトリ名>/` が有効になります。

リポジトリは公開設定にしてください。無料プランでは非公開リポジトリを Pages で
配信できません。ソースが見られて困る内容は含まれていません。

パスはすべて相対指定にしてあるため、リポジトリ名がどうであってもそのまま動きます。
`.nojekyll` は GitHub Pages 側の変換処理を無効にするための空ファイルです。

### 更新するとき

ファイルを変更したら `service-worker.js` の `CACHE_NAME` の版数を必ず上げてください。

```js
const CACHE_NAME = 'barcode-analyzer-v4';
```

版数が同じままだと、端末に保存された古いファイルが使われ続けて変更が反映されません。
版数を上げて push すると、次回起動時に画面上部へ「新しい版があります」と表示され、
利用者が「更新する」を押した時点で切り替わります。
解析中に中身が入れ替わると混乱するため、自動では切り替えません。

## 使い方

| タブ | 用途 |
| --- | --- |
| カメラ | 端末のカメラで連続スキャンする |
| 画像 | 画像ファイルのドロップ・選択・貼り付けから読み取る |
| 手入力 | コードの値を直接入力して解析だけ行う（カメラ不要） |
| サンプル | 動作確認用のバーコードを生成し、その場で読み取らせる |

カメラタブのオプション:

- **枠内のみ解析** … ガイド枠の内側だけをデコードする。処理が軽く誤検出も減る
- **精密モード** … ZXing の TRY_HARDER。読取率が上がるが CPU 負荷も上がる
- **白黒反転も試す** … 白地に黒でない印字（液晶画面・金属刻印など）向け
- **連続スキャン** … 読み取り後もカメラを止めずに次を待つ

## 読取機の設定

解析結果の先頭に「読取機の設定」欄が出ます。出す項目は3つです。

| 項目 | 内容 |
| --- | --- |
| 有効にするシンボル | 機器で有効にすべき形式。メーカー固有ではない一般的な呼び名で出す |
| チェックデジット検証 | 有効にする / 無効にする / 要確認 / 要調査 |
| スタート・ストップ文字 | NW-7 のときだけ。送信の有無で桁数がどう変わるか |

内容はボタン一つでテキストとしてコピーでき、作業報告にそのまま貼れます。

### 複数枚読んで確定させる

NW-7 と Code 39 はチェックデジットが任意仕様のため、1枚では有無を判定できません。
同じ形式を読むたびに一致状況を集計し、偶然の一致である確率を示します。

| 読んだ枚数 | チェックデジットがある確率 | 偶然こう見える確率 |
| --- | --- | --- |
| NW-7 を1枚 | 88.9 % | 12.5 % |
| NW-7 を2枚 | 98.5 % | 1.6 % |
| NW-7 を3枚 | 99.8 % | 0.195 % |
| Code 39 を3枚 | 99.9 % 以上 | 0.001 % |

「ある確率」は、読む前の時点で有無が半々という前提から求めています。

```text
P(あり | n枚すべて一致) = 1 / (1 + p^n)      p は1枚あたり偶然一致する確率
```

客先の事情から「ほぼ付いているはず」と分かっている場合、実際の確率はこれより
高くなります。控えめな見積もりです。一致しない個体が出た場合は、確率ではなく
矛盾の問題になるため割合では表さず、「なし」と表示します。

NW-7 はモジュラス16 を2通り試すため、1枚あたりの誤検出を 1/8 として見積もります。
全枚数で同じ方式に一致した場合のみ、その方式名を設定内容に出します。

3枚そろうと断定表示に変わります。一致した場合も一致しなかった場合も同じ枚数を課します。
不一致は統計的には1枚でもほぼ決着しますが、印刷不良の1枚を掴んだときに誤った設定を
勧めてしまうため、基準を一本にしています。

確率は読むたびに表示されます。同じ値を繰り返し読んでも枚数には数えません。
同じ個体を何度読んでも確度が上がらないためです。

## 表示される情報

- **シンボル種別** … EAN-13、Code 128、QR など。準拠規格・使用可能文字・データ長
- **チェックデジット** … 有無、計算方式（モジュラス10/11/16/43/47/103）、検証結果、計算式
- **桁の構成** … GS1 プレフィックス、メーカーコード、商品コード、CD の色分け表示
- **データの意味** … 国・用途、ISBN/ISSN 換算、日本図書コード、インストアコードの判定
- **GS1 アプリケーション識別子** … GS1-128 などの AI 分解と日付・小数点の復号
- **データ内容** … URL、Wi-Fi 設定、MECARD、vCard などの解釈
- **生データ** … 文字数、文字構成、UTF-8 バイト列

### チェックデジットの扱い

シンボルによって検査の仕組みが違うため、次のように区別して表示します。

| 表示 | 意味 | 該当する例 |
| --- | --- | --- |
| チェックデジット 一致 / 不一致 | データ末尾の CD を再計算して検証した | EAN-13、EAN-8、UPC-A/E、ITF-14 |
| シンボル内蔵の検査文字で検証済み | 読取器が検証して出力から除去済み | Code 128、Code 93、GS1 DataBar |
| 誤り訂正あり（チェックデジットなし） | CD ではなくリード・ソロモン符号で保護 | QR、データマトリックス、Aztec、PDF417 |
| チェックキャラクタ付きの可能性 | 任意仕様の CD が付いていると推定される | Code 39、NW-7 |
| チェックデジットなし | 計算値と一致せず、付与されていないと判断 | Code 39、NW-7 |
| チェックデジット 有無不明 | 規格上任意で、桁数からも確定できない | ITF（14 桁以外） |

## 対応シンボル

1 次元: EAN-13 / EAN-8 / UPC-A / UPC-E / Code 39 / Code 93 / Code 128 / GS1-128 /
ITF / NW-7 (Codabar) / GS1 DataBar

2 次元: QR コード / データマトリックス / Aztec / PDF417 / MaxiCode

## テスト

```bash
node tests/analyzer.test.js
```

解析ロジックの単体テスト。チェックデジット計算、GS1 AI 分解、ISBN/ISSN 換算、
UPC-E 展開、検証項目の種別分類などを検証します。

```bash
node tests/settings.test.js
```

読取機の設定を組み立てるロジックのテスト。形式ごとの判定、複数枚の集計、
スタート・ストップ文字の扱いを検証します。

```bash
node tests/roundtrip.test.js
```

デコード経路の往復テスト。バーコードを生成し、アプリ本体と同じ経路
（輝度バッファ → RGBLuminanceSource → HybridBinarizer → MultiFormatReader）で
復号して元の文字列に戻ることを確認します。

## 構成

```
index.html               画面
manifest.webmanifest     アプリ名、アイコン、全画面表示の指定

.nojekyll                GitHub Pages の変換処理を無効にする空ファイル

js/data.js               GS1 プレフィックス表、AI 表、シンボル仕様
js/analyzer.js           解析ロジック（チェックデジット計算、構造解釈、GS1 AI）
js/settings.js           解析結果から読取機の設定項目を組み立てる
js/render.js             解析結果の描画
js/generate.js           サンプルバーコード生成（EAN/UPC/ITF/Code 39）
js/app.js                カメラ・画像・手入力の制御
js/pwa.js                サービスワーカーの登録と更新通知
vendor/zxing.umd.js      ZXing (@zxing/library 0.21.3) を同梱。オフラインでも動作する

tools/make-icons.js      アイコン生成スクリプト
tests/                   テスト
```

アイコンを作り直す場合は次を実行します。外部ライブラリは不要です。

```bash
node tools/make-icons.js
```

## 制限事項

- メーカーコードが 7 桁型か 9 桁型かはバーコードだけでは判別できません。両方を併記しています。
- Code 39 と NW-7 のチェックキャラクタは任意仕様のため、1枚では「付いている可能性」までしか判定できません。
- NW-7 のモジュラス16 は、規格ではスタート・ストップ文字を合計に含めます。含めない実装の機器も
  あるため両方を試し、一致した方を方式名として出します。モジュラス11 やモジュラス10 を使う
  業界もあり、それらは未対応です。
- サンプル生成が対応するのは EAN-13 / EAN-8 / UPC-A / ITF / Code 39 / QR です
  （同梱の ZXing ビルドは QR 以外の書き出しに対応していません）。
